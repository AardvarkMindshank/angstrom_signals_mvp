Angstrom Signals — Independent Capability Review

Date: 7 November 2026

Basis: Owner briefing note (Angstrom Signals — Capability Brief for AI Review, 7 Nov 2026) plus the current signal catalogue and Lattice/Prism design docs on main.

Role: Independent reviewer. Not a product endorsement.

Overall verdict

The four-layer design (Signals → Groups → Sets → Prism) is coherent and unusually honest for a beginner-facing tool: Unknown, vetoes, point-in-time reconstruction, and a ban on hard-coded “named views” are real strengths.

What the product can express today is strong for describing markets and teaching confluence. It is still weak for many setups experienced discretionary traders actually run, mainly because Sets cannot count, sequence, or compare values across assets, and Prism cannot rank results or study outcomes.

Recommendation: Ship provided Groups and Sets that fit today’s engine first. Add a few core extensions only where they unlock many real setups. Do not market any provided Set as predictive until a registered study on data before 30 October 2024 says otherwise.

Sources note: Claims about “how traders use setups” below cite mainstream teaching and industry write-ups. They are not evidence that those setups predict price. Where this review says weak evidence, treat that as a research warning.

3. Core extensions

Gap from the briefVerdict
1. Group of GroupsDefer. Useful for UX nostalgia (“named views”), not required for most real setups if Sets can AND Groups. Build only if beginners keep asking for one blended number.
2. Counting in SetsDo soon (after sequences, or in parallel). Groups already have a counting contract to copy.
3. SequencesHighest priority core extension. Prefer alert-only strategy state (Waiting → Armed) over free-form “run another evaluation” chains.
4. ComparisonsDo next for relative strength. One relative-strength signal (asset vs Bitcoin or SPY) may unlock more than a general compare-anything language.
5. Outcome testingDo before shipping a large provided library as “useful.” Display stored research results only; refuse Sets whose members lack pre-hold-out history.
6. RankingDo after a few Sets exist; Yes/No tables do not scale.
7. Risk contextLeave out of this layer on purpose.

Important items missing from that list of seven

  • Freshness / Partial treated as if it were Yes (⏳ exists; beginners still ignore it).
  • An explicit “descriptive only” badge on every provided Set until an outcome study exists.
  • Session / calendar filters for US regular hours (useful for stocks; can wait).

6. Testing (data before 30 October 2024 only)

  1. 1. Run an event study, not a P&amp;L backtest: dates a Set turns Yes after No or Unknown; forward returns at fixed horizons (for example 5 and 20 daily bars) versus the same asset’s baseline on all dates.
  2. 2. Eligibility gate: refuse Sets whose members lack pre-hold-out history (sentiment, many flow series, much real intraday). Say so in the product.
  3. 3. Pre-register Set version, horizons and minimum event count (for example 30) before looking at results. Record every try.
  4. 4. No search over thresholds. Changing +30 to +25 is a new try.
  5. 5. Count overlapping Yes windows once per horizon.
  6. 6. Report event count, share positive, and median excess versus baseline — or “too few events.” Never a naked “win rate.”
  7. 7. Research job / CI only; Prism displays stored results and never computes statistics in a page load.
  8. 8. A Set may remain in the product as a teaching description even if results are flat. Promote to “studied” only after the registered run.

A flat result is a successful honesty test, not a product failure.

Single priority order

  1. 1. Ship and polish the no-new-engine library (Trend / Stretch / Flow, pullback / rally, Trend ∩ Flow, Bitcoin filter, Breakout watch as far as today’s signals allow).

Reason: teaches the design immediately; zero architecture risk.

  1. 2. Outcome studies on pre-hold-out data for those Sets.

Reason: stops the library becoming a costume.

  1. 3. Sequences (alert-only state) for breakout, flush and reclaim.

Reason: largest unlock of real discretionary practice.

  1. 4. Relative strength signals (vs Bitcoin / SPY).

Reason: Finviz-class need without a general compare language.

  1. 5. Counting in Sets.

Reason: confirmation Sets without nested mush.

  1. 6. Prism ranking of Yes results / scores.

Reason: watchlist scale.

  1. 7. Funding as a clean signal + crowded-caution Set.

Reason: crypto differentiation versus equity screeners.

  1. 8. Rename and wording pass (Trend Confirmation, Stretch, Lattice / Prism one-liners).

Reason: beginner safety.

  1. 9. Group of Groups only if blended views remain real demand.

Reason: optional sugar.

  1. 10. Never copy social signal spam, hard-coded “systems,” or strategy P&amp;L theatre before risk rules exist.

Uncertainties

  • How deep free funding and open-interest history is for the whole crypto watchlist (affects pre-hold-out studies).
  • Live UI polish (⏳ behaviour, Lattice editor friction) was not re-audited in a signed-in browser in this session; the brief and repository were the basis.
  • Predictive value of any listed setup: weak evidence unless a registered event study says otherwise.
